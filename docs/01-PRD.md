# Startup Simulator — PRD (MVP v0.1)

## 1. 목적
창업 수업에서 조별로 기존 사업 아이디어를 가상 회사로 만들고, 3년 동안 경영 이벤트를 겪으며 전략을 선택한다. 선택 결과로 경영 지표가 바뀌는 것을 보면서 "왜 스타트업이 실패하는가"를 체험하는 교육용 시뮬레이터다.

## 2. 사용자
- 학생 조(3~6명): 한 대의 PC/노트북 화면을 같이 보며 토론하고, 대표 1명이 입력한다.
- 교수자: 조별 결과(JSON)와 토론 근거를 받아 수업 중 비교·피드백한다.

## 3. 핵심 시나리오
1. 조가 기업명, 사업 아이디어, 업종, 대상 고객, 수익모델, 초기 자본, 창업 멤버 수를 입력한다.
2. 시스템이 사업모델 템플릿으로 초기 기업 상태(고객, 매출, 현금, 품질, 사기, 평판, 인력, 월 고정비)를 만든다.
3. 1년 차(생존) → 2년 차(성장) → 3년 차(확장) 순서로 이벤트가 나온다.
4. 이벤트마다 대안 3~4개가 나온다. 대안의 결과는 선택 전에 보이지 않는다.
5. 조는 토론 근거를 적어야 결정을 확정할 수 있다.
6. 결정 직후와 다음 기간 경과 후의 지표 변화가 공개된다.
7. 3년이 끝나거나 파산하면 성과 추이와 학습 보고서가 나온다.

## 4. 범위
### 포함 (MVP)
| 번호 | 기능 | 비고 |
|---|---|---|
| F1 | 기업 정보 입력 | 업종·고객 유형·수익모델은 선택, 아이디어·대상 고객은 자유 입력 |
| F2 | 초기 기업 상태 생성 | 업종 × 수익모델 × 고객 유형 템플릿 |
| F3 | 3단계 × 5개 이벤트 (+대체 이벤트 2개) | 총 17개 작성 |
| F4 | 이벤트당 대안 3개 이상 | 일부 대안은 업종·인력·현금 조건 |
| F5 | 결과 비공개 → 결정 후 공개 | UI에는 비용·조건만 표시, 효과는 전달하지 않음 |
| F6 | 지표 6종 | 매출, 현금, 고객 수, 제품 품질, 팀 사기, 평판 |
| F7 | 토론 근거 기록 | 필수(20자 이상) + 반대 의견 선택 입력 |
| F8 | 추이 차트 + 최종 학습 보고서 | 규칙 기반 자동 생성, 마크다운·JSON 내보내기 |
| F9 | 한국어 UI, 모바일 반응형, 자동 저장, 초기화 | localStorage |

### 제외 (이후 버전)
- 로그인, 다중 조 동시 접속, 교수자 대시보드 (Supabase 단계)
- AI 시나리오 생성 (규칙 엔진은 그대로 두고 이벤트 JSON만 AI가 생성하는 구조로 확장)
- 무작위 시장 충격(랜덤 이벤트). MVP는 결정론적이라 같은 입력이면 같은 결과가 나온다.

## 5. 이벤트 수 해석 (기획서 내 불일치 처리)
요청서에 "3년간 6개 이벤트"와 "단계별 5개 이벤트"가 함께 있다. 두 요구를 모두 살리기 위해 진행 모드를 둔다.
- **수업용(기본)**: 단계별 후보 중 상황에 맞는 3개를 골라 총 9개를 진행한다. (한 수업 시간에 끝나는 분량)
- **전체**: 단계별 후보를 모두 진행해 총 19개를 진행한다(1년 차 6, 2년 차 7, 3년 차 6).
모드는 시작 화면에서 고르고, 중간에 바꿀 수 없다.

## 6. 교육용 가정 (반드시 화면에 표시)
- 이벤트 효과 수치와 업종 템플릿 수치는 수업용으로 단순화한 **가정값**이다. 실제 시장의 평균이 아니다.
- 실패 요인 분류는 CB Insights의 스타트업 사후분석(post-mortem) 정리를 참고한다. 퍼센트는 출처 문서에서 확인된 값만 표시한다. (docs/04 참고)
- 같은 결정이라도 회사 상태에 따라 결과가 달라지도록 설계했다. "정답"이 아니라 "근거 있는 선택"을 평가한다.

## 7. 비기능 요구
- 외부 DB·AI API 키 없이 `npm run dev`만으로 실행된다.
- 계산은 `src/engine`의 순수 TypeScript 함수로 분리한다. React 의존이 없고 vitest로 검증한다.
- 저장소는 `StorageAdapter` 인터페이스 뒤에 둔다. Supabase 어댑터는 같은 인터페이스를 구현하면 된다.
- 모바일 폭(360px)에서 가로 스크롤이 없어야 한다. 키보드 포커스가 보여야 한다.

## 8. 성공 기준
- 새 조가 설정 입력부터 최종 보고서까지 한 번도 막히지 않고 끝낸다. (현금 0 이하 상태에서도 선택 가능한 대안이 항상 존재)
- 어떤 업종 조합에서도 부적절한 이벤트가 나오지 않는다.
- 새로고침·브라우저 재시작 후 같은 화면에서 이어진다.
- 엔진 단위 테스트가 모두 통과한다.

## 9. 클라이언트 번들 주의
MVP는 모든 계산이 브라우저에서 돌아가므로 학생이 개발자 도구로 대안의 효과 수치를 볼 수 있다. 수업에서는 "공정하게 하자"는 규칙으로 운영하고, Supabase 단계에서 결과 계산을 서버(Route Handler)로 옮기면 해결된다.
