# 시뮬레이션 계산 규칙

계산은 모두 `src/engine/rules.ts`의 순수 함수다. 같은 입력이면 항상 같은 결과가 나온다. 아래 숫자는 **교육용 가정값**이며, 업종별 기본값의 기준은 `src/engine/templates.ts`다.

## 1. 시간
- 총 36개월. 이벤트 사이에 월 단위로 시뮬레이션이 돈다.
- 한 해 12개월을 이벤트 수 n개로 나눈다. 예) 2개 → 6·6개월, 5개 → 2·3·2·3·2개월.
- 결정은 이벤트 시점에 즉시 적용되고, 이어서 다음 이벤트까지의 개월이 진행된다.

## 2. 초기 상태 생성
```
고객 수   = 템플릿 초기 고객 × 고객유형 배수 × 수익모델 배수 (최소 3)
ARPU      = 템플릿 ARPU × 고객유형 × 수익모델 배수
월 고정비 = 인원 × 평균 인건비(250) + 업종 고정 운영비 + 마케팅비(100)
인력      = 창업 멤버 수
품질 50~58(업종), 사기 70, 평판 35
```

## 3. 월간 계산 (advanceMonth)
```
가동률 u        = 고객 수 / (인력 × 1인당 처리 고객 수)
신규 고객       = 기본 신규 × (1 + 마케팅비/300) × 평판계수 × 품질계수 × 용량계수 × 네트워크계수
  평판계수      = 0.6 + 0.8 × 평판/100          (0.6 ~ 1.4)
  품질계수      = 0.6 + 0.8 × 품질/100
  용량계수      = u ≤ 1 이면 1, 아니면 max(0.2, 1 − (u − 1))   ← 인력 부족 시 성장 둔화
  네트워크계수  = 플랫폼 업종만 1 + min(1.5, 고객수/3000)
이탈률          = min(0.6, 기본 이탈률 × (1.5 − 품질/100) + 0.05 × max(0, u − 1))
고객 수'        = max(0, 고객 + 신규 − 이탈)       (모두 반올림 정수)
매출            = (고객 + 고객') / 2 × ARPU
비용            = 인건비 + 고정 운영비 + 마케팅비 + 매출 × 원가율 + 부채 × 1.2%
순손익          = 매출 − 비용
현금'           = 현금 + 순손익
```

### 상태 지표 변화
```
품질'  = 품질 − 0.3 − min(4, 3 × max(0, u − 1))
사기'  = 사기 + (60 − 사기) × 0.03 + (순손익 > 0 ? 0.5 : 0) − (현금' < 0 ? 2 : 0) − min(5, 4 × max(0, u − 1))
평판'  = 평판 + (품질' − 평판) × 0.03
모든 값 0~100으로 제한
```

## 4. 예외 상황 처리
### 4.1 현금이 음수가 되는 경우
- 월말 현금 < 0이면 `insolvencyMonths + 1`, 아니면 0으로 되돌린다.
- 현금이 음수인 동안 사기 −2/월, 화면에 위기 배너.
- **선택지 가드**: 대안의 즉시 비용(cost)이 보유 현금보다 크면 비활성("현금 부족"). 현금이 음수일 때도 `cost`가 0인 대안은 항상 선택 가능하다. (모든 이벤트에 비용 0 대안이 있어야 함 — 데이터 검증 테스트)
- 투자·대출처럼 현금이 들어오는 대안은 비용 0이므로 위기 상황의 탈출구가 된다.

### 4.2 파산
다음 중 하나면 `status = bankrupt`로 즉시 종료하고 최종 보고서로 이동한다.
1. 월말 현금 < 0 상태가 **2개월 연속**
2. 현금 < −(초기 자본 × 0.5) (채권자 압류선)

파산 시 점수는 0.4배로 감점되고 보고서에 파산 원인(런웨이 소진 시점, 직전 결정)이 표시된다.

### 4.3 인력 부족
- **하드 조건**: 대안의 `minHeadcount`보다 인력이 적으면 비활성("인력 N명 이상 필요").
- **소프트 페널티**: 가동률 u > 1이면 신규 고객 둔화(용량계수), 이탈 증가, 품질·사기 하락. 결과 화면에 "인력 부족" 경고 표시.
- **이탈**: 사기 < 20이면 매월 인력 −1(최소 1명), 품질 −3, 사기 +5(남은 팀원의 위기 대응). 결과 노트에 "핵심 인력 이탈"로 기록.
- **1인 창업**: 이벤트 `e03-cofounder`는 인력 ≥ 2에서만 나오고, 아니면 `e03f-solo-burnout`로 대체한다.

### 4.4 업종별 부적절한 이벤트
- 이벤트에 `appliesTo`/`applicableWhen`이 있고 조건에 맞지 않으면 `fallbackId` 이벤트로 교체한다. (오프라인 매장은 앱스토어·플랫폼 정책 이벤트 대신 임대료 이벤트)
- 대안 단위로도 `onlyFor`(업종 한정)를 적용한다. 해당 업종이 아니면 대안 자체를 목록에서 제외한다. (비활성이 아니라 제외 — 의미 없는 대안을 보여주지 않기 위해)
- 상황 설명은 `contextByType`로 업종에 맞는 문장을 덧붙인다.

## 5. 결정 적용 (applyDecision)
1. 대안 사용 가능 여부 검사(현금·인력·조건·업종). 불가하면 거부(에러 사유 반환).
2. `cash −= cost`
3. `outcomes`를 위에서부터 훑어 조건이 맞는 첫 결과를 선택.
4. 효과 적용(아래 clamp 규칙) → "결정 직후" 스냅샷
5. 다음 이벤트까지 `advanceMonth` 반복 → "기간 경과 후" 스냅샷
6. 파산이면 중간에 종료.

### clamp 규칙
| 필드 | 규칙 |
|---|---|
| quality, morale, reputation | 0~100 |
| customers | ≥ 0, 정수 |
| headcount | ≥ 1 (채용 시 평균 인건비는 가중 평균, 신규 400) |
| marketingBudget, overhead | ≥ 0 |
| churnRate | 0.01~0.5 |
| cogsRatio | 0~0.95 |
| dilution | 0~90 |

## 6. 종합 점수 (scoreGame)
```
재무 30%   = clamp( (현금 − 부채) / 초기자본 × 50 + 25 ) + (월 순손익 > 0 ? 15 : 0)  → 100 상한
성장 25%   = clamp( 월 매출 / (초기자본 × 0.1) × 100 )
품질 15% / 팀 15% / 평판 15% = 각 지표 값
총점       = 가중합, 파산이면 × 0.4
등급       = A ≥ 80, B ≥ 65, C ≥ 50, D ≥ 35, 그 외 F
```

## 7. 학습 보고서 생성 (generateReport)
규칙 기반이며 AI를 쓰지 않는다.
- 결과 요약: 상태·점수·지표 시작→끝
- 주요 전환점: 결정 직후 6개 지표 정규화 변화량 합이 가장 큰/작은 결정 각 1~2개
- 실패 요인별 대응: 이벤트의 `reason`별로 verdict(strong/ok/weak) 집계
- 토론 기록: 평균 근거 글자 수, 반대 의견을 남긴 결정 비율
- 다음 학습 질문: 가장 낮은 지표 기준 질문 2개

## 8. 템플릿 가정값
`src/engine/templates.ts`가 기준이다. 업종 5종 × 수익모델 5종 × 고객 유형 2종의 곱셈 계수로 구성한다. 구체 수치 표는 밸런스 점검 후 문서에 반영한다.

## 부록 A. 구현에서 확정된 값 (코드가 기준)

- 시장 압력: 매월 이탈률 +0.0009, 고객 획득 기반(acqBase) ×(1−0.008) (`MARKET_CHURN_DRIFT`, `MARKET_ACQ_DECAY`). 수업용 모드는 결정 횟수가 적어 배율 0.85(`SimState.pressure`)를 곱한다. 아무것도 하지 않아도 되는 전략이 가장 유리하지 않도록 올린 값이다.
- 점수 가중치: 재무 .25, 성장 .30, 품질·팀·평판 각 .15. 파산 시 ×0.4. 등급 A≥80, B≥65, C≥50, D≥35, F.
- 성장 점수 기준: 월 매출이 초기 자본 × 0.15 수준일 때 만점 근처. 지분 희석 감점은 계수 0.3.
- 업종 템플릿 수치(고객당 월 매출 / 원가율 / 획득률): SaaS 4 / - / 17, 커머스 6 / .45 / 28, 오프라인 7.5 / .3 / 18 (고정 운영비 500), 콘텐츠 3.5 / - / 19, 플랫폼 2.6 / - / 50. 정확한 값은 `src/engine/templates.ts`.
- 모두 교육용 가정이며 CB Insights의 확인되지 않은 비율은 화면에 표시하지 않는다.

## 부록 B. 투자 유치 규칙 (참고 자료 반영)

참고: 이택경·한국벤처투자·스타트업얼라이언스, 『스타트업 투자유치』(2025 개정증보판).

- 투자금은 "몇 개월 버틸 금액"으로 계산한다(`Effects.cashMonths` = 개월 수 × 월 고정비). 책의 권고는 최소 12개월, 보통 18~24개월이다.
- 시드(e02): 지표 충족 시 18개월치, 지분 15%. 지표가 부족하면 9개월치 브릿지(지분 10%) 또는 실패. 유치 활동 동안 고객 획득이 둔해진다(acqBase −3%): "투자 유치도 본업의 일부".
- 시리즈 A(e11): 조건 수락 24개월치(희석 25%, 지표 부족 시 14개월·30%), 협상 20개월·18%, 경쟁 제안 비교 18개월·16%, 시간을 끌어 런웨이가 4개월 이하이면 6개월·22%.
- 책의 라운드별 투자 금액·기업가치 표(시드 ~50억, 프리A 50~150억, A 150~300억 …)는 국내 IT 기준이며, 시뮬레이션은 회사 규모에 맞춰 월 고정비 배수로 환산했다.
- 투자 유치 총 소요 기간은 4주~7개월(책 도표)이지만 현재 버전은 결과를 즉시 반영한다. 지연 모델은 다음 버전 과제.
